Development Flow

Unified process for humans and AI coding agents to deliver consistent, high‑quality outcomes. This flow emphasizes clarity, fast iteration, and strong documentation.

Why this matters: A shared workflow aligns expectations, speeds up reviews, and makes work traceable across requirements, design, code, and docs.

Overview Flow (TL;DR)

  1. Collect requirements → ask AI to list open questions/edge cases → save as analysis_doc/requirements/<feature>-requirements.md (use repo template at analysis_doc/requirements/requirements-template.md).
  2. Draft a technical plan with AI → human review/sign‑off → save as analysis_doc/requirements/<feature>-tech-plan.md (use repo template at analysis_doc/requirements/tech-plan-template.md).
  3. Implement in small PRs with tests → keep CI green → use flags for safe rollout.
  4. If APIs change, update OpenAPI/Swagger and regenerate docs where needed.
  5. Update appflowy-docs/ pages; add screenshots/snippets. Optionally record decisions with an ADR at analysis_doc/requirements/adr-template.md.

Principles

  • Clarity first: validate requirements and edge cases before writing code.
  • Plan before build: small, checkable technical plans improve throughput.
  • Ship in slices: incremental, verifiable steps reduce risk.
  • Documentation is a deliverable: update docs as part of Done.
  • AI as multiplier: use agents for planning, scaffolding, and documentation—humans retain accountability.

Definition of Ready (DoR)

  • Requirements doc exists with scope, acceptance criteria, and non‑goals.
  • Edge cases and constraints clarified (agent prompts can help enumerate).
  • Owner/DRI identified; dependencies and risks called out.
  • For APIs: preliminary OpenAPI sketch present.

Review Gates and Sign‑offs

  • Technical plan reviewed and approved; record approver and date in the plan.
  • Security/Privacy review required if data model, scopes, or integrations change.

Branching and PR Hygiene

  • Branch naming: feature/<ticket-id>-<short-desc>.
  • Small PRs with a single logical change; linked to requirements/plan.
  • CI gates: lint, types, tests, and API diff (if applicable) must pass.

API Discipline

  • Favor backward‑compatible changes; otherwise bump API version.
  • Treat OpenAPI as source of truth; auto‑generate docs/SDKs where possible.

Observability and Rollback Optional

  • Add logs, metrics, and feature flags for controlled rollout.
  • Provide clear rollback steps in PRs for fast recovery.

Data Migrations Optional

  • Provide up/down migrations; consider backfill strategies and safety on large tables.
  • Require review for schema changes touching PII or critical paths.

Accountability and Traceability

  • Each task links the requirements doc, tech plan, PRs, API diffs, and docs pages.
  • Record decisions (or link ADRs) for impactful architectural changes.

The Flow

  1. Collect requirements
    • Gather business goals, scope, success criteria, constraints.
    • 1.2 Ask AI for clarification prompts: have the agent enumerate missing info, edge cases, data shapes, error states.
    • 1.3 Produce a requirements file: save to the repo as analysis_doc/requirements/[feature]-requirements.md.
  2. Make a technical plan
    • 2.1 Ask AI to draft a plan: include data model, API outline, components, risks, test plan, rollout.
    • 2.2 Review & sign‑off: humans confirm scope, call out gaps, and approve. Save as analysis_doc/requirements/[feature]-tech-plan.md.
  3. Implement
    • Execute in small PRs; keep commits scoped to the plan steps.
    • Write tests alongside code; add logging and metrics.
    • Iterate with the agent to adjust the plan as needed.
    • Ensure CI gates (lint, types, tests) and API diffs (if applicable) pass before merge.
    • Use feature flags for safe rollout; follow branch naming conventions.
  4. Documentation
    • 4.1 Swagger/OpenAPI: If creating APIs, add/modify the spec and regenerate docs where relevant.
    • 4.2 AppFlowy docs: Update appflowy-docs/ with requirements summary, API references, and how‑tos. Use AI for drafting.
    • 4.3 Changelog: Summarize user impact and migration notes.

Deliverables Checklist

  • Requirements: goals, scope, user stories, non‑goals, acceptance criteria.
  • Tech Plan: architecture, data model, APIs, risks, test plan, rollout/flags.
  • Implementation: PRs with tests; CI checks pass; feature flag wiring as needed.
  • Docs: Swagger updated; appflowy-docs/ pages added/updated; screenshots if UI.
  • Observability & Rollback (optional): logs, metrics, flags, and rollback steps provided.
  • Data Migrations (optional): up/down scripts, backfill plan, safety notes.
  • Sign‑offs: reviewers/approvers recorded in the plan or PR.

AI Usage Guidelines

  • Use the agent to ask clarification questions, propose plans, scaffold code, write tests, and draft docs.
  • Always review generated code for security, data privacy, and architectural alignment.
  • Prefer small, verifiable steps; keep the agent’s context fresh with the latest files.
  • Never commit secrets; parameterize credentials and config.
  • Require human approval for schema changes, migrations, and public APIs.

- [ ] Tech plan linked
- [ ] Tests added/updated

Definition of Done

  • All acceptance criteria pass with tests.
  • Swagger and docs reflect the implemented behavior.
  • Feature flags default safe; monitoring in place.
  • Security and privacy checks completed.

Example Workflow with an AI Agent

  1. Create analysis_doc/requirements/mentions-requirements.md; ask the agent for missing edge cases.
  2. Generate analysis_doc/requirements/mentions-tech-plan.md via the agent; human review and sign‑off.
  3. Implement in small PRs; the agent scaffolds code and tests. Humans review.
  4. Update OpenAPI; add appflowy-docs/pages/notifications-inapp.html section; attach screenshots.
