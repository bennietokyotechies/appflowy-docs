Notification System

This page documents AppFlowy's notification system across backend and frontend, starting with a business-focused overview and then deep-diving into architecture, current implementation (Mail), and future In‑App notifications.

Overview

  • Business goal: Keep users informed of relevant events (invites, approvals, mentions, role changes) with reliable delivery and minimal noise.
  • Channels: Email (implemented), In‑App (planned).
  • Coverage: Workspace and content events are supported; Space/Project ACL notifications are planned to align with Access Control.
  • Preferences (planned): Per‑type opt‑in/out, channel selection (email/in‑app), batching frequency, quiet hours.
  • Reliability: SMTP with retry/logging; future WebSocket delivery with optional persistence for offline users.
  • Security: Only notify authorized recipients; do not leak private resource metadata.
  • Non‑goals: Marketing emails; unauthenticated broadcast notifications.

Channels

  • Mail notifications: Implemented via AFCloudMailer using handlebars HTML templates and provider‑agnostic SMTP.
  • In‑app notifications: Planned over existing WebSocket infrastructure with optional DB persistence and API for read/unread.

AS‑IS: Mail Notifications (Implemented)

Implementation references: appflowy-backend/src/mailer.rs, appflowy-backend/src/config/config.rs, templates under appflowy-backend/assets/mailer_templates/build_production/.

  • Workspace:
    • Workspace Invitations — AFCloudMailer::send_workspace_invite → workspace_invitation.html
    • Access Requests — send_workspace_access_request → access_request.html
    • Access Request Approved — send_workspace_access_request_approval_notification → access_request_approved_notification.html
  • Content:
    • Page Mention Notifications — send_page_mention_notification → page_mention_notification.html (batched by background worker; interval/grace in Config.notification)
  • Space (behind feature):
    • Space Invitation — send_space_invitation → space_invitation.html
    • Space Role Update — send_space_role_update → space_role_update.html
    • Space Member Removal — send_space_member_removal → space_member_removal.html
  • Project (behind feature):
    • Project Invitation — send_project_invitation → project_invitation.html
    • Project Role Update — send_project_role_update → project_role_update.html
    • Project Member Removal — send_project_member_removal → project_member_removal.html
  • Auth (separate service):
    • GoTrue authentication emails (confirmation, recovery, magic link) via GoTrue SMTP.

Configuration

  • AppFlowy mailer: APPFLOWY_MAILER_SMTP_HOST|PORT|USERNAME|EMAIL|PASSWORD|TLS_KIND
  • Notifications: APPFLOWY_NOTIFICATION_ENABLE_EMAIL, APPFLOWY_NOTIFICATION_EMAIL_INTERVAL_SECS, APPFLOWY_NOTIFICATION_EMAIL_GRACE_PERIOD_SECS
  • GoTrue SMTP (auth emails): GOTRUE_SMTP_HOST|PORT|USER|PASS
  • Web URL (links in emails): APPFLOWY_WEB_URL

Local Development

Use Mailpit for local testing. See appflowy-backend/doc/MAIL_NOTIFICATION_SETUP.md for docker-compose, .env, and troubleshooting.

TO‑BE: In‑App Notifications (Planned)

References: appflowy-backend/doc/NOTIFICATION_SYSTEM_REQUIREMENTS.md, appflowy-backend/doc/NOTIFICATION_SYSTEM_ANALYSIS.md.

  • Transport: WebSocket endpoints (/ws/v1, /ws/v2/{workspace_id}) and PostgreSQL LISTEN/NOTIFY.
  • Persistence: Optional table af_user_notifications for offline users and read/unread state.
  • APIs (planned):
    • GET /api/user/notifications — list notifications
    • PUT /api/user/notifications/{id}/read — mark read
    • PUT /api/user/notifications/read-all — mark all read
    • GET/PUT /api/user/notification-preferences — read/update preferences
  • Abstraction: a sender that can deliver via email and/or in‑app based on user preferences.

  • End‑to‑end (future): In‑app notification delivery over WS, persistence, read/unread.

Troubleshooting

  • SMTP connection/auth errors: Verify APPFLOWY_MAILER_SMTP_*, TLS kind, provider allow‑list.
  • No emails in dev: Ensure Mailpit is running and env points to localhost:1025.
  • Missing links: Set APPFLOWY_WEB_URL to generate correct accept URLs.
