Okta SAML (Single Sign-On)

This guide walks you through integrating Okta SAML with AppFlowy for Single Sign-On. It summarizes the backend guide at appflowy-backend/doc/OKTA_SAML.md and focuses on quick onboarding for developers.

Prerequisites: You are an Okta admin and have AppFlowy Cloud deployed and reachable from Okta. Ensure GoTrue is accessible at https://<your_host>/gotrue.

Key Service Endpoints

  • ACS URL (Single sign-on URL): https://<your_host>/gotrue/sso/saml/acs
  • Audience URI (SP Entity ID): https://<your_host>/gotrue/sso/saml/metadata

Part 1 — Okta Configuration

  1. In Okta dashboard, switch to Admin view.
  2. Go to Applications → Applications and click Create App Integration.
  3. Select SAML 2.0 and continue.
  4. General settings: set App name to AppFlowy and optionally upload a logo.
  5. SAML settings:
    • Single sign-on URL: https://<your_host>/gotrue/sso/saml/acs
    • Audience URI (SP Entity ID): https://<your_host>/gotrue/sso/saml/metadata
    • Attribute statement (optional): name email → value user.email
  6. Feedback: choose "I'm an Okta customer adding an internal app" and mark as an internal app.
  7. Finish and save.

Part 2 — AppFlowy Configuration

  1. Login as an admin at https://<your_host>/web/login.
  2. Open the Admin panel and go to SSO.
  3. From Okta, copy the application Metadata URL (Applications → AppFlowy → Sign On).
  4. In AppFlowy Admin → Create SSO, paste the metadata URL and create the SSO entry.
  5. Verify under List SSO that the SSO configuration appears.

Assigning Access in Okta

To make AppFlowy visible to users in the Okta dashboard:

  • Go to Okta Admin → Applications → AppFlowy.
  • Use the settings to assign the app to relevant users or groups.

Environment and Troubleshooting

  • Ensure GoTrue and AppFlowy URLs are publicly reachable by Okta (or via a tunnel/VPN during testing).
  • Check JWT secret consistency between GoTrue and AppFlowy. 
    GOTRUE_JWT_SECRET=your_jwt_secret
APPFLOWY_GOTRUE_JWT_SECRET=your_jwt_secret
  • Review backend logs if SSO handshakes fail at ACS/metadata endpoints.
